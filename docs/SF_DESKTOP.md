# SF Desktop — المرحلة التأسيسية

SF هو مسار تطوير مستقل لواجهة سطح مكتب عربية باستخدام PySide6. يبقى المحرك الحالي في هذه المرحلة منفصلاً؛ لا تُشغّل الواجهة مراحل الفحص القديمة تلقائياً.

## المتطلبات

- Python 3.11 أو أحدث (وفق إعداد المشروع الحالي).
- بيئة افتراضية Python.
- PySide6 ضمن الاعتمادية الاختيارية `desktop`.

## التثبيت والتشغيل من نسخة المستودع

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[desktop]"
python -m sf_desktop
```

يوصي دليل Qt for Python باستخدام بيئة افتراضية وتثبيت PySide6 عبر pip. راجع:
https://doc.qt.io/qtforpython-6/gettingstarted.html

## ما هو متاح في هذه المرحلة

- نافذة سطح مكتب عربية RTL.
- تنقل بين لوحة التحكم ومراحل العمل والنطاق والتقارير وتشخيص النظام.
- قراءة معلومات النظام المحلية ووجود الأدوات في PATH دون تشغيلها.
- قراءة ملف النطاق والتحقق الشكلي من IP وCIDR وأسماء المضيفين دون حل DNS أو اتصال شبكي.
- عرض أسماء ملفات HTML الموجودة فقط.
- توليد أو تحديث تقرير HTML مستقل لكل جلسة من السجلات المحفوظة.
- استخدام ترميز HTML آمن، وسياسة CSP صارمة، وكتابة ذرية للملف لتجنب التقارير الجزئية.
- إنشاء جلسات محلية، وسردها، وإغلاقها.
- حفظ أدلة منظمة مع مصدر ومستوى ثقة وحمولة JSON محدودة الحجم.
- استخدام قاعدة بيانات SQLite في `~/.local/share/sf/sf.sqlite3` (أو `$XDG_DATA_HOME/sf/sf.sqlite3`) مع صلاحيات ملفات مقيدة على الأنظمة المتوافقة.

## ما لم يتم توصيله بعد

- تشغيل أي مرحلة فحص من الواجهة.
- اكتشاف أجهزة أو منافذ أو خدمات.
- مطابقة ثغرات أو تشغيل قوالب فحص نشطة.
- إنشاء تقارير الجلسات من بياناتها المحلية؛ لا تزال نتائج مراحل فحص الشبكة غير موصولة.
- ربط الجلسات بمراحل فحص الشبكة.

هذه القيود مقصودة في المرحلة التأسيسية. قبل ربط المحرك ستتم مراجعة كل مسار تنفيذ، وتوحيد فحص النطاق، وتعطيل الاختبارات النشطة غير الضرورية، وضمان وجود سجل واضح لما ينفّذ وما لا ينفّذ.

## مبدأ النطاق

إدراج عنوان في `config/scope.txt` لا يثبت امتلاك الإذن. يجب أن تكون الأهداف مملوكة للمستخدم أو أن يوجد تفويض صريح من مالكها. الواجهة الحالية للقراءة والتحقق الشكلي فقط.
